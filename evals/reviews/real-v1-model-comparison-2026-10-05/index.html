What separates the runs

Wins and regressions

Case-level outcomes are the evidence here. The small net difference in pass counts hides different strengths by dataset.

Gemma’s edge in this sample

  • Faster overall latency: median query time 9.41 s versus 17.14 s.
  • Fewer model calls: median 6 versus 8 calls per run.
  • More compact context/token usage at p95 (65.7k versus 86.2k tokens).
  • Executed without triggering tool-validation retries.

GPT OSS’s edge in this sample

  • Four more complete passes overall, 24 versus 20 (80.0% vs 66.7%).
  • Zero survey failures: 7 survey passes (70%) versus Gemma’s 4 (40%).
  • Generated both required CSV and chart deliverables in both retail analysis cases.
  • Correctly retrieved attached rules in Hindi and calculated exact gold sales and row counts.
  • Passed scope clarification and statistical appendix retrieval.
  • Common limitation: Both models used the wrong qualifying population for missing-customer percentage.
Observed error patterns

Failure categories

These categories summarize the reviewed cases; they are descriptive labels, not mutually exclusive counts.

Run and response failures

With the tool-validation diagnostic length fix applied, zero runs failed at execution time (0 invalid_model_response or infra exceptions across all 30 cases; 29 completed, 1 awaiting clarification). The previous five crashes were resolved by bounding the tool rejection message to 500 characters, allowing the agent loop to recover safely.

Filter and population mistakes

Both models counted missing-customer rows over the raw January slice instead of qualifying invoice lines. This changes both the numerator and denominator.

Omitted requested content

Both models returned the top-country sales amount and invoice count but omitted the country name in the code-switch case. In Hindi document search, both models omitted the requested explicit in-text PDF page number.

Retrieval and evidence gaps

Failures included missing the food-inflation trend passage and incomplete support for survey comparisons. One reviewer flagged an overbroad causal explanation and mislabeled page numbers as chapters.

Deliverable completion

GPT OSS successfully produced both required CSV and PNG chart deliverables for both retail analysis cases. Gemma produced both charts, but its exported CSV in the Hindi case omitted two countries from the 22-country manifest.

Language and table structure

Hindi and code-switched queries were parsed effectively. In Hindi numbers, narrow nonbreaking digit separators triggered false literal string misses in automatic scoring, but manual review confirmed correct underlying values.

Confirmed trace for one GPT OSS failure

For retail-sales-chart-csv, the primary DB trace confirmed this sequence:

  1. list_sources and inspect_schema succeeded.
  2. inspect_artifact was rejected for unknown source_2 artifact.
  3. A search_documents call was rejected for an extra source_id argument.
  4. A later document search returned the rules. The sixth model response then raised a validation error before another tool or answer event.

Cause confirmed and resolved live. The pre-fix crash was caused by an oversized tool-validation diagnostic (646 characters) exceeding the 500-character SafeError.message limit. After bounding the message, the live rerun of retail-export-and-chart-hi generated a 626-character diagnostic in analyze_data, recovered safely, and completed with full CSV and chart deliverables.

Method and limits

Offline review of retained benchmark results. There was one repetition per case, so there is no variance estimate or stable model ranking. Labels were produced through AI-assisted review of saved answers and tool results; no independent human or calibrated native-speaker review was performed. The 30 cases are a small, purpose-built sample and do not establish production quality. The quality scores are descriptive review labels, not a calibrated scale.

Comparison metadata reports that model identity was the only experiment identity difference. The report configurations share the local API origin, application and runner code hash, case fixtures, and configured call/context budgets. Model identity is therefore the intended run difference in this snapshot.
